## [<<](./readme.md) Техническое задание №7

### Реализация gRPC-сервиса для обновления промо-акций

### Цель
Реализовать полный цикл CQRS для обновления промо-акций через gRPC: создать команду, обработчик, модели и gRPC-эндпоинт с использованием Protocol Buffers.

### Требования к реализации

1. **Proto-контракт**
   - Добавить RPC-метод `UpdatePromo` в сервис `PromoService`
   - Определить сообщения `UpdatePromoRequest` и `UpdatePromoResponse`
   - `UpdatePromoRequest`

2. **Команда (Command)**
   - Создать команду `UpdatePromoCommand`
   - Параметр команды — `UpdatePromoRequest`
   - Команда должна возвращать `UpdatePromoResponse`

3. **Обработчик (Handler)**
   - Реализовать обработчик `UpdatePromoCommandHandler` для обработки команды обновления
   - Обработчик должен использовать репозиторий `IPromoRepository` для обновления данных
   - Обработчик должен быть асинхронным и возвращать `UpdatePromoResponse`

4. **Репозиторий**
   - Добавить метод `UpdateAsync(Promo promo)` в интерфейс `IPromoRepository`
   - Реализовать метод в `PromoRepository` с SQL-запросом для обновления записи по ID
   - Метод должен возвращать `bool` (успех операции)

5. **gRPC-сервис**
   - Реализовать метод `UpdatePromo` в `PromoGrpcService`
   - Метод должен принимать `UpdatePromoRequest`, создавать команду и отправлять через MediatR
   - Возвращать `UpdatePromoResponse` с результатом операции

#### Дополнительно
- Все методы должны быть реализованы асинхронно
- Использовать Raw String Literals для SQL-запросов
- Обновление должно происходить по первичному ключу (`Id`)
- Добавить проверку на `null` параметров в репозитории
- Соблюдать принципы CQRS и чистой архитектуры
- Использовать MediatR для разделения бизнес-логики и транспортного слоя
