## [<<](./readme.md)  Техническое задание №10

### Создание модели заказа

### Цель
Реализовать доменную модель заказа для микросервиса управления заказами, включающую информацию о пользователе, статусе заказа, адресе доставки, позициях заказа и параметрах оплаты.

### Требования к реализации

1. **Базовая модель заказа**
   - Создать класс `Order`, наследуемый от `BaseEntity`
   - Все обязательные поля инициализировать (например, значением `default!`)
   - Значения перечислений, если они потребуются, представить в числовом виде

2. **Основные данные заказа**
   - Имя аккаунта пользователя (`AccountName`)
   - Общая сумма заказа (`TotalAmount`)
   - Статус заказа (`OrderStatus Status`)
   - Данные оплаты (модель `Payment`)

3. **Контактная информация**
   - Имя (`FirstName`)
   - Фамилия (`LastName`)
   - Электронная почта (`Email`)

4. **Адрес доставки**
   - Улица и номер дома (`Street`)
   - Город (`City`)
   - Регион/область (`Region`)
   - Почтовый индекс (`PostalCode`)

5. **Позиции заказа**
   - Коллекция `List` с полями:
     - Наименование из каталога (`CatalogName`)
     - Количество (`int Quantity`)
     - Цена за единицу (`UnitPrice`)

6. **Модель оплаты**
   - Способ оплаты (`PaymentMethod Method`)
   - Реквизиты карты (`CardDetails`, опционально)
   - Сумма (`Amount`)
   - Статус оплаты (`PaymentStatus Status`)

### Дополнительные условия
- Использовать строгую типизацию без `null` для строк, коллекций и структур
- Числовые и перечислимые поля должны иметь значения по умолчанию, соответствующие типу
- Все модели должны следовать принципам доменно-ориентированного проектирования (DDD)
